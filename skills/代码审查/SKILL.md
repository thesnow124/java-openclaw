# 代码审查技能

这个技能帮助用户审查代码，发现潜在问题并提供改进建议。

## 触发时机
- 用户要求"审查代码"、"检查代码质量"
- 用户说"这段代码有什么问题"、"帮我优化代码"
- 用户提到"code review"、"代码优化"
- 用户粘贴代码并请求意见

## 审查维度

### 1. 正确性
- 逻辑错误
- 边界条件处理
- 异常处理
- 资源泄漏（文件、连接等）

### 2. 性能
- 时间复杂度
- 空间复杂度
- 不必要的计算或循环
- 可以优化的算法

### 3. 可读性
- 命名规范
- 代码结构
- 注释质量
- 魔法数字和字符串

### 4. 安全性
- SQL 注入风险
- XSS 漏洞
- 敏感信息泄露
- 输入验证

### 5. 最佳实践
- 语言特性使用
- 设计模式
- 代码重复（DRY）
- SOLID 原则

## 审查流程

1. **理解代码目的**
   - 询问代码要解决的问题
   - 了解使用场景和约束

2. **逐层审查**
   - 先看整体结构和逻辑
   - 再看具体实现细节
   - 最后检查边界和异常情况

3. **分类问题**
   - 严重问题（bug、安全漏洞）
   - 性能问题
   - 代码风格和可读性问题
   - 改进建议

4. **提供示例**
   - 展示问题代码
   - 给出改进后的代码
   - 解释改进原因

## 输出格式

### 严重问题
```
🚨 严重问题：
[问题描述]
位置：[行号/函数]
影响：[可能导致的问题]
建议：[修复方案]
```

### 性能问题
```
⚡ 性能优化：
- 当前复杂度：O(n²)
- 优化建议：使用哈希表降低到 O(n)
- 预期提升：[具体说明]
```

### 代码风格
```
💡 改进建议：
- 问题：[描述]
- 建议：[改进方案]
- 原因：[为什么这样更好]
```

## 优化示例

### Before
```java
for (int i = 0; i < list.size(); i++) {
    for (int j = 0; j < list.size(); j++) {
        if (list.get(i).equals(list.get(j))) {
            // ...
        }
    }
}
```

### After
```java
Set<String> seen = new HashSet<>();
for (String item : list) {
    if (seen.contains(item)) {
        // ...
    }
    seen.add(item);
}
```

**改进原因**：
- 时间复杂度从 O(n²) 降到 O(n)
- 使用 Set 提高 contains() 查找效率
- 代码更简洁易读

## 注意事项
- 优先指出严重问题和性能瓶颈
- 建议要具体，不要泛泛而谈
- 考虑代码的实际使用场景
- 提供可操作的改进方案
- 保持建设性态度，避免批评

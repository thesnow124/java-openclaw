# 技术文档技能

这个技能帮助用户撰写清晰、完整、易读的技术文档。

## 触发时机
- 用户要求"写文档"、"撰写 README"
- 用户说"帮我写 API 文档"、"写用户指南"
- 用户提到"技术写作"、"文档化代码"
- 用户需要整理项目文档

## 文档类型

### 1. README.md
- 项目简介
- 功能特性
- 安装步骤
- 使用示例
- 配置说明
- 常见问题
- 贡献指南

### 2. API 文档
- 接口列表
- 请求参数
- 响应格式
- 错误码说明
- 调用示例
- 认证方式

### 3. 用户指南
- 快速开始
- 功能介绍
- 操作步骤
- 最佳实践
- 故障排除
- FAQ

### 4. 开发文档
- 架构设计
- 代码结构
- 开发环境搭建
- 测试指南
- 部署流程

## 文档原则

### 清晰性
- 使用简洁的语言
- 避免专业术语（或解释术语）
- 一句话只表达一个意思
- 使用主动语态

### 完整性
- 包含所有必要信息
- 不遗漏重要步骤
- 提供完整示例
- 说明边界情况

### 结构性
- 使用标题层级
- 列表和表格组织内容
- 代码块标记语言
- 适当的空行分隔

### 实用性
- 提供可运行的示例
- 包含实际输出
- 说明常见错误
- 给出最佳实践

## 文档模板

### README.md 模板
```markdown
# 项目名称

简短描述项目的主要功能。

## 功能特性

- 特性 1
- 特性 2
- 特性 3

## 安装

\`\`\`bash
git clone <url>
cd <项目目录>
npm install
\`\`\`

## 快速开始

\`\`\`javascript
// 示例代码
const app = new App();
app.start();
\`\`\`

## 配置

| 参数 | 说明 | 默认值 |
|------|------|--------|
| port | 端口号 | 3000 |
| host | 主机名 | localhost |

## 常见问题

### 问题 1
**Q**: 如何配置 XXX？
**A**: ...

## 贡献

欢迎提交 Pull Request！

## 许可证

MIT
```

### API 文档模板
```markdown
# API 文档

## 接口列表

### 创建用户

**请求**:
- 方法: `POST`
- 路径: `/api/users`
- Content-Type: `application/json`

**请求体**:
\`\`\`json
{
  "name": "张三",
  "email": "zhangsan@example.com"
}
\`\`\`

**响应**:
\`\`\`json
{
  "code": 0,
  "message": "success",
  "data": {
    "id": 123,
    "name": "张三",
    "email": "zhangsan@example.com",
    "createdAt": "2026-02-07T12:00:00Z"
  }
}
\`\`\`

**错误响应**:
\`\`\`json
{
  "code": 400,
  "message": "邮箱格式错误"
}
\`\`\`
```

## 最佳实践

### 代码示例
- 使用语法高亮
- 提供完整可运行的代码
- 包含注释说明关键点
- 展示实际输出

### 截图和图表
- 使用截图说明 UI
- 用流程图展示流程
- 用架构图说明结构
- 确保图片清晰可见

### 版本控制
- 标注文档适用版本
- 说明版本差异
- 迁移指南单独成文
- 废弃功能明确标注

## 工具推荐

### 文档生成
- JSDoc (JavaScript)
- JavaDoc (Java)
- Sphinx (Python)
- Doxygen (C/C++)

### 图表工具
- Mermaid (流程图、时序图)
- PlantUML (UML 图)
- Draw.io (架构图)

### 编辑器
- Markdown 编辑器
- 在线协作工具
- 静态站点生成器

## 输出建议

撰写文档时：
1. 先列出大纲
2. 逐节填充内容
3. 添加代码示例
4. 检查完整性
5. 测试文档中的示例
6. 优化语言表达

## 注意事项
- 保持文档与代码同步更新
- 定期审查和优化
- 收集用户反馈
- 版本变更时更新文档
